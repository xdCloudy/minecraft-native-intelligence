# Glossary

- **Agent:** one persistent Minecraft-native individual, including runtime identity and lived state.
- **Foundation intelligence/model:** shared learned competence used by many agents; not necessarily an LLM or monolith.
- **Native observation:** structured state/event available through the Minecraft integration under defined information-access rules.
- **Native action:** typed request resolved through ordinary Minecraft mechanics.
- **Player embodiment:** the server-authoritative, player-compatible Minecraft entity/profile through which one agent is rendered, tracked, affected by Survival mechanics, and synchronized to clients.
- **Lifecycle command:** an authorized administrative operation such as `/spawn ai-agent <username>`; not an in-world instruction perceived by the agent.
- **Legal action:** an action permitted by current mechanics, state, timing, and server policy; legality does not imply strategic wisdom.
- **Agent runtime:** lifecycle and orchestration layer binding shared competence to one individual's state.
- **Personal state:** identity, memories, relationships, goals, personality, habits, preferences, and optional adapters owned by one agent.
- **Memory:** durable, queryable agent state with provenance; distinct from transient model context.
- **Consolidation:** auditable restructuring of experience into more durable or general memory/skill representations.
- **Grounding:** a causal connection among world observations, language/representations, decisions, actions, and outcomes.
- **Autonomy:** selecting and revising activities without all goals originating as external commands.
- **Emergent behaviour:** behaviour arising from learning and interaction rather than being directly scripted to appear.
- **Minecraft-native ontology:** agent-facing concepts grounded in its world, without required external-computer concepts.
- **Experiment:** bounded evidence-gathering implementation; not automatically the production architecture.
- **Evaluation scenario:** versioned declaration of a question, environment, information boundaries, scaffolding, seeds, metrics, baselines, and artifacts used to test a claim.
- **Evaluation result:** immutable evidence record linking trial-level outcomes, failures, artifacts, variance, and interpretation to one exact evaluation scenario.
- **Experiment run:** execution/provenance record for a scenario and configuration, including source revision, attempts, logs, and artifact hashes; distinct from scientific interpretation.
- **Privileged input:** evaluator/operator/environment information unavailable to the tested agent under the baseline information-access policy.
- **Scaffolding:** declared scripted, heuristic, oracle, authored, or operator assistance that may influence a run and must not be credited as learned behaviour.
- **Quality gate:** required validation appropriate to a change or release stage; gates range from static checks through integration, statistical, security, and longitudinal testing.
- **Runtime boundary:** asynchronous interface separating the Minecraft Java integration from the replaceable research/model runtime.
