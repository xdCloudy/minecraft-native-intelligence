## Production readiness gates

Per-item readiness advances only when declared acceptance evidence is present. `CI validated` does not imply integrated capability; `integrated into main` requires main-revision provenance. `Production validated` requires installation/update/rollback, compatibility, player-equivalent mechanics, in-game validation, security/privacy/consent, runtime reliability, monitoring/resource budgets, recovery and user/operator documentation as applicable.

| Agent capability | No production-ready Minecraft-native agent capability recorded on main. | Reproducible held-out Minecraft scenarios showing acquired behavior and excluding scripted/privileged execution. |

## Rejected, deferred and out-of-scope approaches

| ID | Approach | Decision | Evidence-based rationale |
|---|---|---|---|
| `REJ-001` | Treat a language model issuing commands through Mineflayer as the project definition | out_of_scope | It bypasses the native player interface and does not establish persistent, grounded, self-directed learning. LLM components remain eligible as bounded baselines. |
| `REJ-002` | Use privileged world mutation, teleportation or hidden state to inflate task success | rejected_by_invariant | Violates player-equivalent Survival mechanics and information-access parity. |
| `REJ-003` | Count scripted construction templates or demonstrations as learned creativity | rejected_by_invariant | Predefined behavior is not evidence of acquired skill, adaptation, novelty or autonomous project selection. |
| `REJ-004` | Select a final foundation architecture before native interface and matched evaluation exist | deferred | Current evidence cannot justify lock-in; compare architectures after action/observation contracts and baselines are stable. |
